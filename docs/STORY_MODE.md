# Story mode (`/gentruyen`)

A **fiction story** narrated over the user's own images (for example AI images made one per ~8 s of an earlier narration). Separate from the archival workflow (`/gendoc`, `/genvideo`, `docs/WORKFLOW.md`).

**Do not use from the archival workflow:** archival media search (one exception: real photos of the crew's named vehicle when Z-Image cannot draw it, `docs/ZIMAGE.md` §5), fact-check (`FACTS.md`), "(illustrative)" labels, licence rows for the user's images, `doc.py plan` / `templates/archival/`, the drawn-character budget, `description.py` CC lists, `evidence.py` (exception: a story with real archival photos on screen gets the same evidence pack as `/genvideo`, built by `story_done.py`, see step 10). **No background music since 2026-11-22 (user): `doc.py story` places no music beds, only card SFX, word SFX and the opening ambience; `story.music: true` in brief.json only when the user asks.** **Shared with it:** voice (`split`, `tts`, `assemble`), card SFX and music levels (music only a faint trace, about 31 dB under the voice since 2026-11-14; SFX set from their own loudness under the voice), subscribe overlay, the studio review stop, export via `scripts/export.py`, QA.

The layout here, one picture per story beat anchored to its words, is right for a story and wrong for an archival film: never carry it over to `/genvideo`.

## Input (`input/`)
Either layout:
- **A (side by side):** `input/<name>.txt` (script) + `input/<name>/` (images `001.png`, `002.png`…) + optional `input/<name>.srt` + optional `input/<name>_… scene.txt` (prompts).
- **B (one folder):** `input/<name>/` with `script.txt` (or the only script `.txt`), the images, optional one `.srt`, optional `*scene*.txt` / `*prompt*.txt`.

The `.srt` here is the **timing the images were made for** (one image per `seconds_per_image` of it, default: its length ÷ image count, rounded to 0.5 s, i.e. 8 s for Whisk scenes); it is not used as narration. Without it the images are spread evenly over the new voice. The prompts file (JSON lines `{"scenes 12": "…"}` or one prompt per line) only fills each clip's `need` text. Folders starting with `_` are ignored (old jobs).

Optional `input/<name>.json` (or `job.json` in the folder): `title`, `language`, `voice`, and `"story": {"grade": "archival|film|modern|none", "seconds_per_image": 8, "music": true, "card_sfx": true, "title_card": true}`.

## Language and market
`ingest` detects the script language (ja / vi / es / de / en; `language` overrides) and picks the narrator (`VOICES` in `doc.py`: en Brian, es Alberto, de Robert Ranger, vi Tung Dang, ja Koichi Yashiro). Every on-screen word follows it: title, `CHAPTER`/`CHƯƠNG`/`CAPÍTULO`/`KAPITEL`, cards, subtitles.

## Voice
Stories use AI84 eleven_v4 in whole chunks without emotion tags (cut into sentences by Whisper), with the language's voice from `VOICES` in doc.py (user 2026-11-16: ElevenLabs v4 for every language again; the MiniMax cloned voices TUNG_DUY_V2/LS_US are opt-in via job.json `voice`). The script must pass `storycheck.py` before any voice, so the voice is always generated here, never outside.

## Images without the user's folder: Z-Image local (default since 2026-11-14)
When a story arrives without images, generate them on the local **Z-Image Turbo** (ComfyUI) by default: read `docs/ZIMAGE.md` for the settings, the prompt rules and the runner. User rule 2026-11-14: TST Auto Generate Image is broken and switched off, so do not use it unless the user asks for it again. On Vitebsk (2026-11-14) TST ran ~24 s per image (87 images in 30 min, then abandoned), Z-Image ~9 s.

**Order of work (the three time savers, user 2026-11-14 after a ~5 h Vitebsk run):**
1. **Z-Image from the start.** No TST trial, no reference-image prompts converted later.
2. **Write every prompt in Z-Image form from the start**, following `docs/ZIMAGE.md` "What Z-Image cannot draw" (no helmets, radios with dials, headphones, phones, maps, writing, insignia, accordion close-ups, people lying down). On Vitebsk the prompts were written for TST with helmets, radios and papers, and ~210 of 699 images (30 %) had to be remade, about 1 h 15 min.
3a. **No picture of an earlier story again** (user 2026-11-28, story 14: "ảnh này giống y đúc ảnh phim nào trước đó… khâu prompt vấn đề"; all 646 pictures were newly generated, yet 15 were the same picture as one of an earlier story and 5 pairs were the same picture twice). Z-Image falls back on one stock composition for a generic line, whatever else the prompt says (a night charge under flares came out as the daylight column of marching soldiers). So:
   - **Prompts:** a beat is never only "soldiers march through snow", "tanks advance across a field", "a bridge over a frozen river", "a transport plane on an airfield", "a burning village". Each prompt names what only this moment has (the named man and what his hands are doing, the object the sentence is about, a particular building or vehicle detail) and puts it in the foreground; the troops, the snow and the sky are background. At most one wide establishing shot per chapter.
   - **Check:** `PY scripts/imagerepeat.py JOB` after the batch (and after every remake) compares every picture with all earlier generated pictures in `C:/ComfyUI/output` (earlier stories' projects are deleted, their pictures stay there) by what they show. `!!` at similarity 0.95 or more (the same picture again) and for twins inside the story; `qa/imagerepeat-*.jpg` shows each pair. Remake those beats as another picture **of the same sentence**: what the sentence names, seen another way (foreground, shot size, angle), not another seed of the same prompt and not an unrelated subject (story 14: the remake for "There was a great flash and a crack" was a quiet lamp-lit alley, the one for "The tracks squealed on every turn" a peasant barn; the user caught the first in the studio). After the remakes, read each new picture against its beat text. The studio gate runs the same check.
3. **Defect-check while Z-Image is still running**: every finished block of ~100 images goes to a review agent at once (`story_sheet.py … --qa A-B`), and the remakes are queued next to the main batch. Only run `doc.py story` and the draft render after the last remake is checked: `doc.py story` copies the images into `media/scenes/`, so an image changed later needs `doc.py story` again before any render (Vitebsk: one render was thrown away because it used the old images).

- **Characters (no reference images).** Each main character gets one fixed **Character Sheet** in `_gen/chars.json` (full name; in brackets nationality, age, face shape, hair, headgear, uniform, one signature item; never helmets or headphones in a sheet), and the film one `Seed:`. `scripts/zimage_prompts.py` repeats the sheet in every image where that character appears; that keeps faces the same.
  - **New faces every story.** First render one portrait per sheet (a small jobs file through `zimage_batch.py`, same seed) and put them on one contact sheet next to every archived ref in `stories/published/refs/*/`; rewrite any sheet that could pass for an earlier character (same build, face shape, hair, cap, pose). Give the hero a visibly different description from the last stories: age, build, face (round/broad/bearded/glasses), hair, headgear. Königsberg (2026-11-09): Hartmut came out as the Berlin hero's twin (lean angular face, black side cap) and the user saw it on the uploaded thumbnails. Copy the portraits to `stories/published/refs/<story>/` at delivery; `story_done.py` deletes the input folder.
  - Scene prompts name characters as `@Name` (`{"n", "refs", "prompt"}` JSON lines, `refs` = the visible main characters); the converter turns `@Name` into the name plus the sheet.
  - **Every person without a sheet gets a nationality and a place in the prompt**, e.g. "a Vietnamese fishing-boat owner with a Southern Vietnamese face … at Bến Đình harbour, Vũng Tàu, South Vietnam". Do the same for crowds ("Vietnamese fishermen in conical hats"), uniforms ("South Vietnamese (ARVN) military policeman") and money or documents ("South Vietnamese 5-đồng banknote"). Story 89 Ngọn Hải Đăng (2026-11-03): 19 images came out European. The user's words: "lúc làm ảnh ko ghi rõ quốc gia à?"
  - Check every image with people but no sheet for nationality and era in the defect check.
  - **House style = Người Gác Đêm (2026-10-30 story the viewers liked): black-and-white war-era documentary photography, no colour.** Each prompt starts with shot size, angle, camera move and light (e.g. "Medium shot, eye level, static, hard lamplight."); the converter adds the style opener and the tail sentence. `story.grade` stays `archival` (the renderer's monochrome grade), so a stray colour image is fine.
- **TST Auto Generate Image (only when the user asks for it again).** MCP server `auto-image` (`http://127.0.0.1:47100/mcp`): `get_usage` first (6,000 images/day), `generate_image(prompt, aspect_ratio="16:9", reference_images=[abs paths], output_folder)`, `wait_for_jobs`; character lock with `refs/<Name>.png` + "the man from reference image 1 (@Name)". Bulk runs: `PY scripts/story_images.py "input/<name>" prompts_*.jsonl --from 11 --wait`. The defect rules below still apply.
- **Pacing.** About one image per 8 s of voice (one per scene beat), anchored like the user's own images. **Hard limit: no image on screen over 8 s** (user rule 2026-11-10: "dài tối đa 8s thôi, chia khớp voice") (`doc.py story` prints `!!` for each; brief `story.max_image_secs`): long static images read as low-effort content to YouTube (monetization risk) and drift off the words (user, Königsberg 2026-11-10). Each image shows what is being said while it is on screen; check a contact sheet of images with their beat text, not only faces. Check a contact sheet of the first 10 images before queueing the rest, then spot-check about every 20th image (`story_sheet.py … 20-699:34`).
- **Output.** `zimage_batch.py` saves to `input/<name>/` as `001.png`, `002.png`…; keep the prompts files, so `ingest --story` and `doc.py story` work unchanged.
- **Defect check on EVERY image, whatever the source** (Flow, TST, Z-Image, the user's own folder), before `doc.py story` and again on regenerated ones. User rule 2026-11-12: viewers blame the channel for missing the review, not the AI ("khán giả chửi vì kiểm duyệt thiếu"). On Army Group Centre a loader came out with bat/elf ears in 61 images, because the sheet asked for "big protruding ears".
  - Look for: abnormal ears; melted or doubled faces; 3 arms or 3 legs; a hand from nowhere; 6+ fingers or fused hands; merged bodies; floating parts; gibberish text; swastikas; modern objects; absurd vehicles; **wrong scale** (a tank, gun or truck no bigger than the man in or beside it; user note on Korsun 2026-11-15: "xe bé người gần bằng xe"). Put every recurring vehicle's images on one contact sheet and check scale across all of them; one toy-sized vehicle means the sheet wording is wrong, so fix the sheet (`docs/ZIMAGE.md` §3) and remake the whole class. On the same sheet check the **model**: the crew's named tank or gun must look like that model (a viewer wrote "It sure ain't a Panther" on Refugees, 2026-11-15); see `docs/ZIMAGE.md` §5 "The hero's vehicle must read as its named model".
  - How: make 9-per-sheet numbered sheets (`PY scripts/story_sheet.py … --qa`) and split them over parallel review agents (~200 images each). Regenerate every flagged image with a changed prompt, then check the new ones the same way.
  - Never write exaggerated anatomy into a character's look ("big/protruding ears", "huge hands", "long neck"): image models turn it into a deformity.
  - **Prompt words that cause defects** (Army Group Centre, 2026-11-12: 150 of 794 images had to be remade, and one pass of review agents missed half; always run a second strict pass):
    - "no readable text" or a written letter/form/newspaper draws gibberish → show papers closed or folded, an envelope, a pencil beside a closed notebook.
    - "waving", "raising a hand", "hand frozen in the air" draws a Nazi-style salute → both hands on the hatch rim, rifle slung, paddle at shoulder height.
    - "road" draws modern asphalt with lane markings and guardrails → "a rutted sandy dirt track", or a forest clearing.
    - Bare "trucks" come out 1960s with EU plates → "canvas-covered German Opel Blitz trucks".
    - Tanks get double or triple muzzles and fuse with trucks → "its long gun a single smooth tube", other vehicles "parked several metres away".
    - Glasses with "fire/orange glow" turn into glowing eyes.
  - Write the fix as positive wording of what IS there. Negative phrases ("no X") do nothing on CFG-1 turbo models and naming X draws it.
- **Beats and image timing without a user SRT.** Voice first (`tts`, `assemble`), then cut ~8 s beats from the real voice timing (`timing.json` words, pauses included; ≤ 8 s each, on sentence or clause ends). Character counts (~115 per beat) are only a fallback before the voice exists: on Königsberg (2026-11-10) they gave 70–299-character beats and 12–21 s images. `PY scripts/story_beats.py projects/JOB "input/<name>.srt"` does it: it writes `beats.json` (the beat texts for prompts and contact sheets) and the image SRT with beat k at [8k, 8k+8), and `doc.py story` then starts each image on its beat's first word. `ingest --story` needs ≥ 2 images, so it can run on placeholders while the images render (the script digest does not change when images are replaced).

## Steps
0. **Start gate (first thing, user still present):** do every step that can raise a permission prompt (copies from the `evidence/` junction to drive F:, writes outside the project) now, and tell the user in Vietnamese to click Allow, so the rest runs unattended. See `docs/WORKFLOW.md` section 0.
1. `PY scripts/doc.py ingest --story [--only NAME]` → `projects/<id>/` with `genre: story`.
2. Run `PY scripts/storycheck.py <script>` against earlier stories (`docs/STORY_WRITING.md`); it also flags character, pet and hometown names an earlier story already used (viewers noticed "a soldier named Beddo in all these videos", 2026-11-15). It also flags **character types and running gags** an earlier story already built on (viewers 2026-11-17: "Railway timetable again, seriously?", "the tank crewmen are a prototype of the crewmen in the previous videos"; `docs/STORY_WRITING.md` "New cast types every story"): rewrite that character's trade, habit and every scene of the gag, and compare the listed cast introductions with "Cast types already used" in `stories/published/LOG.md`. Fix every `!!` yourself by rewriting the script before `split`/`tts`, without asking (user rule 2026-11-12), and report what you changed. **Then the core check** (user 2026-11-28, "tôi cần chắc chắn": stories 14 and 15 had other names, trades, forms and fates and both turned on a paper with a wrong hour and wounded men left behind; storycheck compares words and the review skill reads one script alone, so both passed): run `PY scripts/storycore.py JOB` and do what it prints. When the script went through a batch check (`/soat-lo-truyen`, below) and was not edited since, the verdict is taken over and only stories published or started after it are compared (a few lines, no reading of the script). Otherwise a **fresh reader sub-agent** (one that did not write or fix the script) reads the entire script and records the core (`--set-core`), then the comparison is recorded (`--verdict different` or `--verdict same --with ... --why ...`). "same" stops the story before any voice: tell the user which earlier story it repeats (a story with another core is written in the app; renaming a prop does not change what it turns on). The gate refuses a story without a verdict for the current script text (`story-core`); after any script edit run the check again. **Batch check before any story is built** (user 2026-11-28: "sai codex hay antigravity nó chạy vụ này riêng, sau đó qua 1 lượt ở workflow sẽ nhẹ"): the skill `/soat-lo-truyen <folder>` runs `storycore.py --batch` and `storycheck.py` over a whole folder of new scripts. Then run `/kiem-duyet-kich-ban <script> --truyen` (fiction mode: stray notes and internal continuity only, no fact-check; it does not replace storycheck.py) with `--auto` (it fixes group 1 and clear group 2 itself, without asking) and show the user the before/after table in your report. Then read the story and write a short `STORY.md` (chapters, emotional curve, title). Fiction: no `FACTS.md`. Chapters come from `# Heading` lines in the script; if it has none, propose chapter points to the user (or add them to `sentences.json` chapters) before voicing.
3. `split JOB` → review emotions → `tts JOB` (dry run, credits) → `tts JOB --run` (spend pre-authorized) → `assemble JOB`.
4. `PY scripts/doc.py story JOB` (brief `story.title_after`: sentence id the title card follows, default the opening paragraph). It also builds, every story (brief switches in brackets): sound before picture: black under an ambience before the first image (`cold_black`, `open_ambience`), with a typed notice on it that the images are illustrations and the story is meant to be listened to, typewriter keys and a bell under it (`notice`: false = off, or `{kicker, lines}` to reword; texts in story.py `NOTICE` for en/vi/de/es; user rule 2026-11-12 after a viewer called the AI pictures "impossible to watch"). `assemble` leaves 10 s before the first sentence for it, so an older story needs `assemble` again before `story`; the title over a symbol shot if `story.title_image` names one (make it with Z-Image, `docs/ZIMAGE.md`: the signature prop in the film's style, dark top third); the animated subscribe overlay with its click/bell SFX on the narration's subscribe call, else on the channel mention in the welcome or sign-off (`subscribe`); a 10 s end screen whose slots match YouTube's end-screen elements (`end_screen`, length `end_screen_secs`, 5–20 s). Then: one clip per image anchored to the word where its part of the story starts (word alignment with the image SRT), title card after the opening paragraph, a chapter card in each chapter pause, music beds per chapter (mood from the sentences' emotions, tiled with crossfades; the ducked music is levelled to a faint trace, about 29–33 dB under the voice (2026-11-14), and adjusted per bed), card SFX at measured levels, grain + burned-in subtitles. Rerun after every `assemble`.
   - Music that must follow the plot (climaxes, espionage beds), add brief `story.music_plan`: `[{"sentence": "S167", "mood": "spyintrigue", "emotion": "tense"}, …]`. Each bed runs from its sentence to the next entry. Mostly-neutral sentences otherwise give one bed for the whole film (story 51). Also set `story.alt` for fallback beds.
   - **Required in every story:** the effect "Phim cũ nhẹ" (`old_film` preset) covers the whole film on the `fx` track (user rule, 2026-11-02). `doc.py story` adds it, or stretches an existing one, from 0 to the film's end on every run. Turn it off only if the user asks (`story.old_film: false`).
   - **Combat SFX on words (required):** every shot, explosion, bombardment, landing, air attack or sabotage in the narration gets a library SFX on the exact word: gunshot, mgburst, artillery, shellburst, boom, navalblast, planedive, planeflyby… (user, story 51). List them in brief `story.word_sfx`: `[{"sentence": "S458", "word": "landing", "sfx": "boom", "f": "01", "under": 8, "length": 4}]`. `doc.py story` places them on every run. Use `under` 5–8 dB (LUFS of the part that plays): peaks then land 2–7 dB under the voice's peaks. Keep them ≥ ~10 s apart.
   - Card SFX are set in LUFS against the voice: hits 3 dB under it, riser 4 dB, whoosh and drop 6 dB. Before the studio stop, check them on an sfx-only premix stem.
5. Refine with `doc.py ops` / the studio MCP tools: date tags, lower thirds, quote cards, story SFX on words, ambience.
6. `PY scripts/doc.py build JOB --only picture` (GPU draft render).
7. **Studio review: stop and wait.** First `PY scripts/gate.py JOB studio` until it prints PASS (`docs/WORKFLOW.md` Gates: `doc.py studio` refuses without it), then `doc.py studio JOB`. Fix notes over MCP until the user approves.
8. After the user's approval, export with `PY scripts/export.py JOB` (never the studio's export button; it runs the `export` gate itself), then `PY scripts/gate.py JOB deliver --video …` (runs `doc.py qa`).
9. Deliver to `output/<id>/`:
   - the video and a 1280×720 thumbnail. **Only the style is fixed. The picture and the text layout are designed new for every story** (user rule 2026-11-23). Until then every story thumbnail was the same picture: the hero on the right looking at the viewer, two lines on the left, a red circle and an arrow. A channel whose thumbnails all look alike reads as mass-produced: the user's Vietnamese espionage channel lost monetization for "repetitive content" (2026-11).
     - **Fixed (the channel's look):** gritty black-and-white photo with aged, torn edges; overlay text in the worn military stencil (Saira Stencil One, condensed), white/grey, no glow; red hand-drawn notes when notes are used; bottom-right corner clear for the duration badge.
     - **Free (invent it from this story, never from a template):** what the picture shows and how it is framed; where the text sits, how many lines it has and how big each is; the form of the hook; whether there are red notes and which. Start from the one image only this story has (its signature prop, key scene, place, vehicle or enemy) and build the frame around it. The hero's face is optional. There is no default layout and no list of layouts to rotate through.
     - **Hook text** is never the title and is written for this story's stake. Its form changes too: do not reuse the last thumbnails' pattern (for example number + noun, or a two-word question) or their strong verb.
     - **Before generating:** read "Thumbnails already used" in `stories/published/LOG.md` and look at the stored files in `stories/published/thumbs/`. The new thumbnail must differ from each of the last 5 in subject, framing, subject position and text position. Then write the Z-Image prompt for that composition (the hero's Character Sheet only if he is in it, a few seeds to choose from) with a quiet dark area where the text will go.
     - **Measured check:** `PY scripts/thumbrepeat.py out.jpg --story --sheet qa/thumb-vs-last.jpg` compares the layout with the last 5 story thumbnails; fix every `!!` (the `deliver` gate runs it too).
     - **Draw and check:** `PY scripts/story_thumb.py spec.json out.jpg` (spec `lines`: any number of text lines, each with its own position, size, alignment and tilt). View the result next to the last 5 thumbnails at small size: if it could be mistaken for one of them, redo the composition, not only the words. Both files renamed to the input script's file name;
   - **Archival photos in a story** (named vehicle Z-Image cannot draw, `docs/ZIMAGE.md` §5): credits as strict as `/genvideo`. On screen every photo shows its credit (Bundesarchiv: "Bundesarchiv, Bild <signature> / <photographer> / CC BY-SA 3.0 de", from `doc.py media pick`); the description gets the block from `PY scripts/description.py JOB … --cc-links --credits-only` (each file's signature + Commons link, licence deed) above the hashtags. Never ship a CC photo without both.
   - `description_youtube.txt` and the thumbnail follow the user's GEM brief for the espionage channel (`G:\YOUTUBE\TRUYEN_TINH_BAO_VN\GEM GPT RA MÔ TẢ TRUYEN_TINH_BAO - HƯ CẤU.txt`, read it each time; it is written for the Vietnamese channel: for an English story keep its rules and layout in English, without the Vietnamese disclaimer, CTA and tags): 3 title options (50–90 chars, place first, strong verb, emotional end); a hook sentence containing "truyện tình báo", 2–3 teasing lines with no spoiler, 5 timestamped parts (part 5 at 70–80 % of the length), the fiction disclaimer and the "Góc Khuất Tình Báo" CTA verbatim, hashtags, and tags starting "truyện tình báo, truyện trinh thám". Thumbnail text: from the GEM brief keep only the font and colour (worn military stencil, Saira Stencil One condensed, white/grey, no glow) and short lines of 2–4 words; its fixed layout (two horizontal lines on the left) no longer applies, the layout is free (see the thumbnail rule above). No archival source or CC list.
   Give the tags and hashtags in chat. Never upload. Then ask the user whether the video is uploaded.
10. **After the user confirms the upload: clean up** (stories are AI images, so there is no evidence pack).
    1. Add the story's row to `stories/published/LOG.md`: opening frame, hero trade and region, signature prop, twist (from STORY.md). Add a row to "Thumbnails already used" in the same file (what the picture shows, framing, where the subject and the text sit, the hook's form); `story_done.py` keeps the thumbnail itself in `stories/published/thumbs/`. Add each named character's type (trade, habit, running gag, pet) to "Cast types already used" in the same file, and a `name = regex` line to `stories/motifs.txt` for every new type, so `storycheck.py` blocks it next time.
    2. Run `PY scripts/story_done.py JOB` (dry run: lists what is kept, what is deleted and the GB freed).
    3. Then run `PY scripts/story_done.py JOB --run`. **When real archival photos are on screen** (rows in `LICENSES.md`), it first builds the copyright evidence pack `evidence/stories/<name>/` with `evidence.py --story` (user 2026-11-15: "y bên genvideo", to dispute a false claim): uploaded video, thumbnail and description, every picture (generated scenes as own work with their prompts and sheets, archival photos plus the original downloads in `project/media/orig/`), each Commons licence record and page, `INDEX.csv` (film time → file → source → licence) and `README.md`. It refuses to delete anything if the pack fails. The pack sits under `evidence/stories/`, outside the archival repeat and thumbnail checks. It keeps the final script and STORY.md in `stories/published/`, the storycheck corpus. It deletes `projects/<id>/`, the story's inputs in `input/` (script, image folder, image SRT, prompts) and `output/<id>/` (the video is on YouTube; `--keep-output` keeps it once).
    4. **Shared code changed in this session** (a script, a doc, `stories/motifs.txt`): `PY -m pytest tests -q`, then commit exactly those files on `main` and `git push origin main`, without asking (user 2026-11-25; details in `docs/WORKFLOW.md` stage 14). `story_done.py --run` deletes the working files itself: never ask "delete?".
    4. Music beds and SFX stay in the shared library `assets/music`, `assets/sfx` and are reused by both paths. Any music or SFX file found only inside the project is moved into `assets/<music|sfx>/from-<id>/` first.

Checked on the story the user made with this workflow before (388 images, 65 min): the generic alignment places the images within 0.42 s (median) of the hand-tuned edit, 90 % within 1.3 s.
